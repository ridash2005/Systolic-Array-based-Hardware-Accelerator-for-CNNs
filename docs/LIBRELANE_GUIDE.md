# LibreLane ASIC Implementation Guide

This guide details the complete RTL-to-GDSII flow using **LibreLane** (formerly OpenLane 2). It covers installation, project structure, configuration parameters, and execution steps to transform the Verilog source into a manufacturable layout for the SkyWater 130nm process.

---

## 1. Overview

**LibreLane** is an automated RTL-to-GDSII flow based on open-source tools. It performs the following steps:
1.  **Synthesis (Yosys)**: Converts Verilog to Gate-Level Netlist.
2.  **Floorplan (OpenROAD)**: Defines core area, IO placement, and Power Grid.
3.  **Placement (OpenROAD)**: Places standard cells on the grid.
4.  **CTS (OpenROAD)**: Builds the Clock Tree to distribute the clock signal.
5.  **Routing (OpenROAD)**: Connects the cells using metal layers.
6.  **Signoff (Magic/Netgen)**: Performs DRC (Design Rule Checks) and LVS (Layout vs Schematic) checks.

## 2. Prerequisites

### Software
- **Docker**: The recommended way to run LibreLane to ensure environment reproducibility.

- **RAM**: Minimum 16GB (32GB+ recommended for large arrays).
- **Disk**: 20GB free space (ASIC run databases are large).

## 3. Project Structure & Configuration

The ASIC-specific files are isolated in `scripts/librelane/`.

```
Systolic-Array-based-Hardware-Accelerator-for-CNNs/
├── src/rtl/                     # RTL Source Files
├── scripts/librelane/           # ASIC Configuration
│   ├── config.json              # Main Flow Configuration
│   ├── constraints.sdc          # Timing Constraints (Synopsys Design Constraints)
│   ├── pin_order.cfg            # IO Pin Placement Rule
│   └── README.md                # Config Helper
└── runs/                        # Autogenerated Output Folder
```

### 3.1 Main Configuration (`config.json`)
This JSON file controls every aspect of the flow. Key industry-grade parameters used:

*   **`DESIGN_NAME`**: `top_wrapper`
*   **`CLOCK_PERIOD`**: `100.0` ns (10 MHz). Relaxed for first pass, can be tightened to 10ns (100MHz).
*   **`FP_CORE_UTIL`**: `35`. Core Utilization %. Low value (35%) chosen to ease routing of the dense systolic interconnects.
*   **`PL_TARGET_DENSITY_PCT`**: `40`. Target placement density.
*   **`CTS_CLK_BUFFERS`**: List of specific Clock Buffers (`sky130_fd_sc_hd__clkbuf_*`) to use for building a balanced clock tree.
*   **`RUN_ANTENNA_REPAIR`**: `true`. Inserts diodes to fix antenna rule violations (charge accumulation during manufacturing).
*   **`RT_MAX_LAYER`**: `met4`. Restricts routing to Metal 4 (Sky130 has 5 layers), saving the top layer for power distribution.

### 3.2 Timing Constraints (`constraints.sdc`)
Defines the timing intent for the Static Timing Analysis (STA) tool (OpenSTA).
*   **Clocks**: Defines `clk`, `A_in_serial_clk`, and `B_in_serial_clk`.
*   **IO Delays**: Specifies how long signals take to arrive at inputs/outputs, crucial for interface timing closure.
*   **Uncertainty**: Adds margins for clock jitter and manufacturing variations.

### 3.3 Pin Configuration (`pin_order.cfg`)
Physical location of pins, critical for PCB design.
*   **North**: Matrix A Inputs.
*   **South**: Matrix B Inputs.
*   **East**: Matrix C Outputs.
*   **West**: Control Signals (`clk`, `rst_n`, `start`).

## 4. Execution Instructions

### Step 1: Install LibreLane
```bash
pip install --user librelane
```

### Step 2: Run the Flow (Dockerized)
This command pulls the Docker image and runs the flow inside it, mounting your current directory.

```bash
# Navigate to project root
cd Systolic-Array-based-Hardware-Accelerator-for-CNNs

# Execute
librelane scripts/librelane/config.json --design-dir . --dockerized
```

**Common Options:**
*   `--start-from "placement"`: Skip synthesis/floorplan and restart from placement.
*   `--log-level VERBOSE`: Show detailed tool logs.
*   `--overwrite`: Delete the previous run with the same tag (if any).

## 5. Analyzing Results

Upon completion, results are stored in `runs/RUN_YYYY-MM-DD_HH-MM-SS/`.

### Key Output Files (`runs/.../final/`)
*   **`top_wrapper.gds`**: The final **GDSII** layout file. This is what you send to the foundry.
*   **`top_wrapper.lef`**: Library Exchange Format. Abstract view of the macro for inclusion in larger chips.
*   **`top_wrapper.spef`**: Parasitics. RC values for accurate post-layout simulation.
*   **`top_wrapper.v`**: The synthesized, PnR-optimized netlist.

### Reviewing Logs (`runs/.../logs/`)
If the flow fails, check these directories:
1.  **`synthesis/1-synthesis.log`**: RTL errors, mapping issues.
2.  **`floorplan/2-initial_fp.log`**: Core area too small?
3.  **`placement/`**: Congestion reports. If overflow > 0%, increase area or reduce density.
4.  **`routing/`**: DRC violations.
5.  **`signoff/`**: Magic DRC/LVS error counts.

## 6. Troubleshooting Guide

### "Permission Denied" (Yosys/OpenROAD)
*   **Cause**: Running natively without tools in PATH.
*   **Fix**: Always use the `--dockerized` flag unless you have a full native EDA stack installed.

### "Detailed Placement Failed"
*   **Cause**: The design is too dense; cells are overlapping or have no room to move.
*   **Fix**: Decrease `PL_TARGET_DENSITY_PCT` (e.g., to 35) or decrease `FP_CORE_UTIL` (e.g., to 30) in `config.json`.

### "Antenna Violations"
*   **Cause**: Long wires connected to gate inputs accumulate charge.
*   **Fix**: Ensure `"RUN_ANTENNA_REPAIR": true` is set.

### "Timing Violations" (Setup/Hold)
*   **Setup (Too Slow)**: Reduce target frequency (increase `CLOCK_PERIOD`).
*   **Hold (Race Condition)**: The tool usually fixes this by inserting buffers. If failing, check if input delay constraints in SDC are realistic.
